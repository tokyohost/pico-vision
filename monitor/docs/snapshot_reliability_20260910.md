# Snapshot 网络与 ESP32 性能验证（2026-09-10）

## 结论

完整事务可以超过 16KiB；限制仍保留在单条 PV1 负载和单条解压 JSON 上。事务发送器将每片 JSON 控制在 4096 字节以内，设备收齐后应用操作，不会把整个事务重新拼成一条大 JSON 再解析。

新增序列化事务预算：ESP32-S3 为 256KiB，RP2040 为 64KiB，通过 PONG 的 snapshot_chunks.max_bytes 协商。预算统计唯一分片的解压 JSON 字节，包含事务信封与操作；不是最终快照的体积上限，也不代表等量的堆内存。MicroPython 对象开销、旧快照、暂存操作和新快照会额外占用内存，内存不足时原子提交失败并释放暂存事务。

## 对比测量

Windows CPython、固定随机种子 17、每组构帧（包含压缩）7 次，表中为中位数。没有刷写连接的设备，没有测量 ESP32 原生 CPU、实际 Wi-Fi 丢包率或端到端延迟。压缩后线路字节随随机会话标识略有变化。

## 已验证路径

- 40950 字节（RP2040）和 164808 字节（ESP32-S3）业务快照通过真实 PV1 校验、zlib 解压、JSON 解析和事务提交，内容完全一致；读取按 37 字节拆分，最终只产生一次匹配请求的 ACK。
- 单条解压后超过 16KiB 的 JSONZ 即使压缩很小仍被拒绝。
- 同次轮询的多个事务以及显示缓存使用完整替换，已删除插件字段不复活。
- 注入网络抖动、CPU 处理停顿、缺片和提交过慢，验证 400ms 预算失败、基线清理和下一批全量恢复。CPU/网络延迟由可控时钟模拟，不是物理网络仿真。
- WebSocket 半行读取超时保留已收片段；发送中断、超时关闭、发送锁争用、无换行大包均有覆盖。异常关闭立即释放 socket，避免 websocket-client 默认三秒关闭握手。
- 超出设备事务预算或提交 MemoryError 时，不发布半份快照。

## 优化内容

连续数组项共享一个 items 操作；分片装箱采用编码长度累计，避免反复编码整组操作；数组容量用指数探测减少大数组重复编码。设备全量根覆盖不再复制旧快照，按序迭代分片操作，长文本取消逐片补齐到完整长度的空格分配。WebSocket 发送整条 PV1 消息，不再经过 USB 511 字节分块。

## 实机验收入口

开启 display.dev 后，设备在最终 ACK 后输出 SNAPSHOT_TIMING，包含 PARTS、BYTES、APPLY 和 TRANSACTION。APPLY 是最终应用操作的板端耗时，TRANSACTION 是从第一片到提交的时间，包含接收间隔与处理时间；Monitor 的构帧到最终 ACK 耗时才是主机端整批预算。ACK 证明协议层提交，不代表屏幕已完成绘制。

建议分别采集冷启动全量、稳定增量、切换股票样式、Wi-Fi 弱信号和渲染繁忙时的 p50/p95/p99、超时率与 gc.mem_free()。400ms 是成功判定预算，不是对任意弱网、驱动阻塞和数据量的按时成功交付保证。

## 回归结果

本轮相关用例合计 158 项通过：snapshot 17、WebSocket 10、CDC 10、Monitor 115、ESP32 历史缓存 6。snapshot 用例额外包含两种固件 160 轮随机数据往返及 5 类网络/CPU 场景。CRC 损坏线路帧不会提交，后续全量事务可恢复。

在 Monitor 目录运行 `python -m unittest discover -s tests -p test_snapshot_transfer.py`、`test_websocket_transport.py`、`test_usb_cdc_framework.py` 和 `test_monitor.py`（分别替换 `-p` 参数）。ESP32 历史缓存用例位于 `../esp32-s3/tests/test_history_increase.py`。
