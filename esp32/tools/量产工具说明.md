# ESP32-S3 量产工具

双击同目录 `start_production.cmd` 打开中文 GUI，确认 SDK 和代码目录后点击 **开始量产**，随后插入 USB。也会处理启动时已连接的候选设备。多块设备依次处理。

界面显示单板流程进度条和状态灯：**红灯**表示正在处理设备（识别、写入、校验及复位期间请勿拔出）；**绿灯**表示写入、校验和复位全部完成，可拔出设备；确认拔出后转为**黄灯**，等待下一块。失败时显示黄灯及“本块失败 · 等待重试”，不显示绿灯；停止时显示灰灯，已完成结果则保留绿灯。

流程进度按阶段分配：识别 0–10%、SDK 写入 10–55%、重枚举 55–60%、代码同步 60–90%、校验 90–98%、最终复位 98%，成功后为 100%。已有兼容 SDK 时直接进入代码同步阶段。百分比表示流程推进，不代表剩余时间；只有校验和复位成功才显示 100%。

- 自动读取 `flash.sh` 最后一条 `esptool write_flash/write-flash` 命令的芯片、波特率、地址及镜像系列，不执行整个历史脚本。串口号由实际设备替换。
- 仅在 `flash.sh` 同目录、同硬件规格、同固件系列中按数字版本比较。当前选择 **N16R8 v1.0.69**，不会被官方 MicroPython v1.28.0 或 N8R8 系列混淆。新增同系列更高版本 bin 后，下一次开始量产自动选用。
- 已有 SDK 的判断来自真实 REPL：ESP32-S3 平台及 `fn_protocol` API v1 可用。已有兼容定制 SDK（包括旧版本）直接同步代码；不会强制升级。如果需要最新 SDK，需先让设备进入 ROM 下载模式再接入。
- 无可用 SDK 时，通过 esptool ROM 握手核对 ESP32-S3，确认 Flash 容量满足文件名规格，刷入 SDK，等待同一物理 USB 设备重新枚举，再部署代码。N16R8 固件用于 16 MB Flash / 8 MB 八线 PSRAM 板卡；工具不自动探测 PSRAM 接线规格，批次中请使用匹配板型。
- 复用 `pico-project/tools/mpremote_stream_copy.py`，默认代码库 `pico-project/esp32-s3`。同步完成后逐文件核对 SHA-256，确认设备身份并复位后计为成功。过滤规则与原同步器一致，默认增量同步，不删除设备中本地已移除的旧文件。
- 双 CDC 接口按 USB 物理位置归为同一设备。正常完成或失败后不会在本次连接中反复刷写；拔出至少 **3 秒**再接入才能重试。停止按钮等待当前设备完成后停止；重新开始会重新检查已连接设备。
- 日志自动保存在同目录 `production_logs`；失败显示在日志中，不计为成功。成功表示 SDK 可访问、代码内容一致且复位命令成功，不代表已完成屏幕、网络等整机功能测试。

请使用数据 USB 线，关闭占用串口的 Monitor、Thonny 等软件。支持发现 Espressif 原生 USB、CP210x、CH34x、FTDI；VID 仅筛选候选，不作为确认芯片的依据。没有自动下载电路的板卡，需按住 BOOT 插入 USB（必要时点按 RESET）。串口驱动必须正常安装。若 USB 模式切换后物理位置和序列号均无法保持，工具会报错停止，不会猜测其他设备的 COM 口。

启动脚本优先使用项目 `.venv`，否则使用 PATH 中的 `python`。需要 Python 3.10+（含 Tkinter）。缺少依赖时在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\esp32\tools\production_requirements.txt
```

测试命令（不访问或刷写真实设备）：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s .\esp32\tools\tests -v
```
